Cách hoạt động

  1. Nghiên cứu - Claude phân tích codebase để hiểu phạm vi và cấu trúc
  2. Phân rã - chia công việc thành 5 tới 30 đơn vị độc lập

# /batch

Điều phối thay đổi quy mô lớn trên codebase một cách song song. Mô tả điều bạn muốn thay đổi, và `/batch` lo phần còn lại: nghiên cứu, lập kế hoạch, thực thi song song và tạo pull request.

## Cách hoạt động

1. **Nghiên cứu** - Claude phân tích codebase để hiểu phạm vi và cấu trúc
2. **Phân rã** - chia công việc thành 5 tới 30 đơn vị độc lập
3. **Lập kế hoạch** - trình bày kế hoạch để bạn duyệt trước khi đổi bất kỳ dòng code nào
4. **Thực thi** - sinh một agent nền cho mỗi đơn vị, mỗi agent trong một [git worktree](^Tính năng của git tạo thư mục làm việc riêng dùng chung một repository. Mỗi agent có file và nhánh riêng, không xung đột) cô lập
5. **Bàn giao** - mỗi agent triển khai đơn vị của mình, chạy test và mở pull request

## Cách dùng

```
/batch chuyển src/ từ Solid sang React
/batch thêm structured logging cho mọi API handler
/batch cập nhật mọi file test dùng vitest thay cho jest
```

## Yêu cầu

- Phải ở trong một **git repository** (cô lập bằng worktree cần git)
- Thay đổi phải **phân rã được** thành các đơn vị độc lập
- Hiệu quả nhất khi có bộ test tốt để mỗi agent tự kiểm chứng kết quả

## Cô lập bằng worktree

Mỗi đơn vị chạy trong git worktree riêng tại `<repo>/.claude/worktrees/<name>`. Điều này có nghĩa:

- Các agent làm việc song song mà không xung đột file
- Mỗi đơn vị có nhánh riêng
- Đơn vị thất bại không ảnh hưởng đơn vị khác
- Worktree được dọn tự động khi agent kết thúc mà không có thay đổi

## Khi nào dùng

- Migration quy mô lớn (framework, thư viện, phiên bản API)
- Refactor toàn codebase (đổi khuôn mẫu tên, cập nhật import)
- Thêm tính năng nhất quán trên nhiều file (logging, xử lý lỗi, test)
- Mọi thay đổi chạm nhiều file theo một khuôn mẫu lặp lại
