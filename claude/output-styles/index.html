Output Styles

Output style là một bộ chỉ dẫn quyết định vai trò, giọng điệu và định dạng trả lời của Claude cho cả phiên. Bạn chọn một lần, không phải nhắc lại trong từng prompt. Claude Code có sẵn bốn style ngoài mặc định, và bạn có thể viết style của riêng mình.

Bắt đầu nhanh

  1. Chạy /output-style để xem danh sách, rồi /output-style concise để chuyển
  2. Hoặc tạo file .claude/output-styles/my-style.md với frontmatter và chỉ dẫn
  3. Chọn style của bạn bằng /output-style my-style
  4. Claude dùng style mới từ tin nhắn kế tiếp

Các style có sẵn

Style Thay đổi gì Dùng khi
Default Không thêm chỉ dẫn nào; system prompt chuẩn cho công việc lập trình Mặc định
Proactive Bắt tay làm ngay, tự đưa ra giả định hợp lý thay vì hỏi các quyết định thường ngày Bạn muốn Claude cứ làm tiếp, sai thì bạn chỉnh
Concise Câu đầu nêu kết quả; bỏ dẫn nhập, tường thuật từng bước và tóm tắt cuối Câu trả lời mặc định dài hơn bạn muốn
Explanatory Thêm các khối Insight ngắn giải thích lý do đằng sau code Đang làm quen codebase, muốn hiểu cả lý do
Learning Như Explanatory, và để lại vài đoạn code (TODO(human)) cho bạn tự viết Muốn vừa xong việc vừa luyện tay

Một vài chi tiết đáng biết:

  • Proactive không đổi chế độ quyềnManual, Accept Edits, Plan, Auto… quyết định lời gọi công cụ nào cần hỏi. Xem built-in/modes. Lệnh nào cần hỏi thì vẫn hỏi. Nó vẫn dặn Claude hỏi bạn trước khi xoá dữ liệu hay đụng vào hệ thống production
  • Concise vẫn viết đầy đủ khi bạn yêu cầu giải thích, và khi cần để bạn hành động an toàn: báo lỗi, test thất bại, cảnh báo bảo mật
  • Learning dừng lại chờ bạn viết code ở chỗ TODO(human), rồi nhận xét và làm tiếp

Giá trị trong file settings phân biệt hoa thường: viết Proactive, Concise, Explanatory, Learning. Viết sai (như explanatory) sẽ ra style Default. Lệnh /output-style thì không phân biệt hoa thường.

# Output Styles

Output style là một bộ chỉ dẫn quyết định **vai trò, giọng điệu và định dạng trả lời** của Claude cho cả phiên. Bạn chọn một lần, không phải nhắc lại trong từng prompt. Claude Code có sẵn bốn style ngoài mặc định, và bạn có thể viết style của riêng mình.

## Bắt đầu nhanh

1. Chạy `/output-style` để xem danh sách, rồi `/output-style concise` để chuyển
2. Hoặc tạo file `.claude/output-styles/my-style.md` với frontmatter và chỉ dẫn
3. Chọn style của bạn bằng `/output-style my-style`
4. Claude dùng style mới từ tin nhắn kế tiếp

## Các style có sẵn

| Style | Thay đổi gì | Dùng khi |
|---|---|---|
| **Default** | Không thêm chỉ dẫn nào; system prompt chuẩn cho công việc lập trình | Mặc định |
| **Proactive** | Bắt tay làm ngay, tự đưa ra giả định hợp lý thay vì hỏi các quyết định thường ngày | Bạn muốn Claude cứ làm tiếp, sai thì bạn chỉnh |
| **Concise** | Câu đầu nêu kết quả; bỏ dẫn nhập, tường thuật từng bước và tóm tắt cuối | Câu trả lời mặc định dài hơn bạn muốn |
| **Explanatory** | Thêm các khối `Insight` ngắn giải thích lý do đằng sau code | Đang làm quen codebase, muốn hiểu cả lý do |
| **Learning** | Như Explanatory, và để lại vài đoạn code (`TODO(human)`) cho bạn tự viết | Muốn vừa xong việc vừa luyện tay |

Một vài chi tiết đáng biết:

- **Proactive** không đổi [chế độ quyền](^Manual, Accept Edits, Plan, Auto… quyết định lời gọi công cụ nào cần hỏi. Xem built-in/modes). Lệnh nào cần hỏi thì vẫn hỏi. Nó vẫn dặn Claude hỏi bạn trước khi xoá dữ liệu hay đụng vào hệ thống production
- **Concise** vẫn viết đầy đủ khi bạn yêu cầu giải thích, và khi cần để bạn hành động an toàn: báo lỗi, test thất bại, cảnh báo bảo mật
- **Learning** dừng lại chờ bạn viết code ở chỗ `TODO(human)`, rồi nhận xét và làm tiếp

| Cách | Chi tiết |
|---|---|
| Lệnh | `/output-style <style>`. Không có tham số thì liệt kê và đánh dấu style hiện tại |
| Menu | `/config` → **Output style** |
| VS Code | Gõ `/` trong ô prompt → **Output styles** |
| File settings | `"outputStyle": "Explanatory"` |

Lệnh và menu lưu lựa chọn vào `.claude/settings.local.json`. Muốn đặt mặc định cho mọi dự án, ghi `outputStyle` vào `~/.claude/settings.json`.
