Hooks

Hooks là các script tuỳ chỉnh tự động chạy ở những thời điểm xác định trong phiên Claude Code. Chúng cho phép bạn chặn lời gọi công cụ, kiểm tra thay đổi, áp luật và gắn Claude vào quy trình phát triển sẵn có.

Bắt đầu nhanh

  1. Mở .claude/settings.json (hoặc chạy /hooks trong phiên)
  2. Thêm một hook dưới sự kiện bạn muốn chặn (vd. PreToolUse, PostToolUse)
  3. Viết script đọc JSON từ stdin, kiểm tra, rồi thoát với mã 0 (cho phép) hoặc 2 (chặn)
  4. Khởi động lại Claude Code. Hooks được chụp lại lúc khởi động

Hooks hoạt động thế nào

Mỗi hành động Claude thực hiện đều phát ra một sự kiện hookMột điểm có tên trong vòng đời nơi hooks có thể chạy, như PreToolUse hay PostToolUse. Cấu hình của bạn cho Claude Code biết cần theo dõi sự kiện nào và chạy gì khi chúng xảy ra.

  1. Sự kiện phát ra. Claude sắp gọi công cụ, trả lời xong, bắt đầu phiên...
  2. Matcher kiểm tra. Nếu bạn định nghĩa matcher (regex trên tên công cụ hoặc nguồn sự kiện), chỉ sự kiện khớp mới kích hoạt hook
  3. Hook handler chạy. Script của bạn (hoặc endpoint HTTP, hoặc prompt LLM) nhận bối cảnh JSON qua stdin
  4. Claude hành động theo kết quả. Mã thoát 0 là cho phép. Mã thoát 2 là chặn (với sự kiện hỗ trợ). Output JSON cho kiểm soát chi tiết hơn

Các sự kiện hook

Hooks phát ra ở các điểm sau trong vòng đời của Claude. Sự kiện trong vòng lặp agentic phát ra lặp lại khi Claude làm việc:

Sự kiện Khi nào phát ra Chặn được?
SessionStart Phiên bắt đầu hoặc tiếp tục Không
UserPromptSubmit Bạn gửi prompt, trước khi Claude xử lý Có
PreToolUse Trước khi một lời gọi công cụ chạy Có
PermissionRequest Khi hộp thoại xin quyền sắp hiện Có
PostToolUse Sau khi công cụ chạy thành công Chỉ phản hồi
PostToolUseFailure Sau khi công cụ chạy thất bại Chỉ phản hồi
Stop Khi Claude trả lời xong Có (buộc tiếp tục)
SubagentStart Khi một subagent được sinh ra Không
SubagentStop Khi một subagent kết thúc Có
Notification Khi Claude gửi thông báo Không
TeammateIdle Khi một thành viên agent team sắp rảnh Có
TaskCompleted Khi một task đang được đánh dấu hoàn thành Có
ConfigChange Khi một file cấu hình thay đổi Có
PreCompact Trước khi nén bối cảnh Không
SessionEnd Khi phiên kết thúc Không

Cấu hình

Hooks được định nghĩa trong file settings. Có ba cấp lồng nhau:

  1. Sự kiện hook: điểm vòng đời nào cần phản hồi
  2. Nhóm matcher: bộ lọc regex (vd. chỉ cho công cụ Bash)
  3. Hook handler: script, endpoint, prompt hoặc agent sẽ chạy
json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "command": ".claude/hooks/validate-bash.sh"
          }
        ]
      }
    ]
  }
}

Mẫu matcher

matcher là regex so khớp với các trường khác nhau tuỳ sự kiện:

  • Sự kiện công cụ (PreToolUse, PostToolUse...): khớp tool_name (vd. Bash, Edit|Write, mcp__github__.*)
  • SessionStart: khớp cách phiên bắt đầu (startup, resume, clear, compact)
  • SessionEnd: khớp lý do phiên kết thúc (clear, logout, other)
  • Notification: khớp loại thông báo (permission_prompt, idle_prompt)
  • SubagentStart/Stop: khớp loại agent (Bash, Explore, Plan, hoặc tên tuỳ chỉnh)

Bỏ trống matcher hoặc dùng "*" để khớp tất cả. Một số sự kiện như UserPromptSubmit và Stop không hỗ trợ matcher và luôn phát ra.

Các loại hook handler

Loại Cách hoạt động
command Chạy lệnh shell. Nhận JSON qua stdin. Giao tiếp bằng mã thoát và stdout
http Gửi JSON bằng POST tới một URL. Body phản hồi quyết định kết quả
prompt Gửi đầu vào cho một model Claude để đánh giá có/không trong một lượt
agent Sinh subagent có công cụ (Read, Grep, Glob) để kiểm chứng điều kiện

Không phải sự kiện nào cũng hỗ trợ mọi loại. SessionStart, Notification, PreCompact và một số khác chỉ hỗ trợ hook command.

Đầu vào và đầu ra

Hook của bạn nhận gì

Mọi hook nhận JSON này qua stdin (hoặc làm body POST với hook HTTP):

json
{
  "session_id": "abc123",
  "cwd": "/home/user/my-project",
  "permission_mode": "default",
  "hook_event_name": "PreToolUse",
  "tool_name": "Bash",
  "tool_input": {
    "command": "npm test"
  }
}

Trường tool_name và tool_input là riêng theo sự kiện. Mỗi sự kiện thêm trường riêng bên cạnh các trường chung.

Mã thoát

Mã Ý nghĩa
0 Thành công. Claude Code đọc stdout để lấy output JSON (nếu có)
2 Lỗi chặn. stderr được gửi cho Claude như thông báo lỗi. Tác dụng tuỳ sự kiện
Khác Lỗi không chặn. stderr hiện ở chế độ verbose, việc thực thi tiếp tục

Output JSON

Để kiểm soát chi tiết hơn, thoát với mã 0 và in JSON ra stdout thay vì chỉ dùng mã thoát:

json
{
  "hookSpecificOutput": {
    "hookEventName": "PreToolUse",
    "permissionDecision": "deny",
    "permissionDecisionReason": "Đã chặn lệnh phá huỷ"
  }
}

Các trường JSON chung dùng được với mọi sự kiện:

Trường Tác dụng
continue Nếu false, Claude dừng xử lý hoàn toàn
stopReason Thông báo hiện cho người dùng khi continue là false
suppressOutput Nếu true, ẩn stdout khỏi chế độ verbose
systemMessage Thông báo cảnh báo hiện cho người dùng

Async Hooks

Thêm "async": true vào hook command để chạy nó dưới nền. Claude tiếp tục làm việc ngay trong khi hook chạy. Kết quả được gửi ở lượt hội thoại kế tiếp.

json
{
  "type": "command",
  "command": ".claude/hooks/run-tests.sh",
  "async": true,
  "timeout": 120
}

Async hook không thể chặn lời gọi công cụ hay trả về quyết định. Chúng hữu ích để chạy bộ test, deploy hay gửi thông báo song song với việc của Claude.

Khuôn mẫu thường gặp

Chặn lệnh nguy hiểm (PreToolUse trên Bash): phân tích tool_input.command, kiểm tra rm -rf hoặc mẫu phá huỷ khác, thoát mã 2 để chặn.

Tự định dạng sau khi sửa (PostToolUse trên Write|Edit): chạy linter hoặc formatter trên file vừa đổi, gửi output lại cho Claude.

Kiểm tra kiểu sau thay đổi (PostToolUse trên Write|Edit): chạy tsc --no-emit sau khi sửa TypeScript, Claude thấy lỗi và sửa các chỗ gọi.

Ngăn code trùng lặp (PostToolUse trên Write): khởi chạy một phiên Claude thứ hai để review code mới so với khuôn mẫu sẵn có.

Cổng chất lượng trước khi dừng (Stop): kiểm tra test pass hoặc file bắt buộc tồn tại trước khi cho Claude kết thúc.

Chèn môi trường lúc khởi động (SessionStart): ghi các câu lệnh export vào $CLAUDE_ENV_FILE để đặt biến môi trường cho phiên.

Cần nhiều hơn một script?

Shell hook khởi chạy tiến trình mới cho mỗi sự kiện. Nếu bạn muốn trạng thái tồn tại suốt phiên, UI sống như một dải phía trên ô prompt hay một pane gắn cạnh, hoặc gọi trực tiếp tính năng của Claude Code, hãy viết một modHook JavaScript chạy bên trong phiên của bạn. Xem mục mods. Mod là function hook được phát hành dưới dạng plugin.

Mẹo

  • Hooks được chụp lại lúc khởi động phiên. Khởi động lại Claude sau khi đổi cấu hình hook
  • Dùng $CLAUDE_PROJECT_DIR trong lệnh để tham chiếu script tương đối với gốc dự án
  • Dùng /hooks trong phiên để xem, thêm và xoá hook một cách tương tác
  • Chạy claude --debug để xem chi tiết thực thi hook và mã thoát
  • Đặt "disableAllHooks": true trong settings để tạm tắt mọi hook
  • Giữ hook chạy nhanh. Timeout mặc định là 600 giây cho command, 30 giây cho prompt
  • Đặt biến shell trong ngoặc kép ("$VAR" thay vì $VAR) và kiểm tra đầu vào. Hook script chạy với toàn quyền người dùng của bạn
  • Với công cụ MCP, khớp bằng mẫu như mcp__github__.* hoặc mcp__.*__write.*
  • Hook prompt và agent trả về {"ok": true/false, "reason": "..."} thay vì dùng mã thoát

| Khác | Lỗi không chặn. stderr hiện ở chế độ verbose, việc thực thi tiếp tục |

### Output JSON

Để kiểm soát chi tiết hơn, thoát với mã 0 và in JSON ra stdout thay vì chỉ dùng mã thoát:

```json
{
  "hookSpecificOutput": {
    "hookEventName": "PreToolUse",
    "permissionDecision": "deny",
    "permissionDecisionReason": "Đã chặn lệnh phá huỷ"
  }
}
```

Các trường JSON chung dùng được với mọi sự kiện:

| Trường | Tác dụng |
|---|---|
| `continue` | Nếu `false`, Claude dừng xử lý hoàn toàn |
| `stopReason` | Thông báo hiện cho người dùng khi `continue` là false |
| `suppressOutput` | Nếu `true`, ẩn stdout khỏi chế độ verbose |
| `systemMessage` | Thông báo cảnh báo hiện cho người dùng |

## Async Hooks

Thêm `"async": true` vào hook command để chạy nó dưới nền. Claude tiếp tục làm việc ngay trong khi hook chạy. Kết quả được gửi ở lượt hội thoại kế tiếp.

```json
{
  "type": "command",
  "command": ".claude/hooks/run-tests.sh",
  "async": true,
  "timeout": 120
}
```

Async hook không thể chặn lời gọi công cụ hay trả về quyết định. Chúng hữu ích để chạy bộ test, deploy hay gửi thông báo song song với việc của Claude.

## Khuôn mẫu thường gặp

**Chặn lệnh nguy hiểm** (PreToolUse trên Bash): phân tích `tool_input.command`, kiểm tra `rm -rf` hoặc mẫu phá huỷ khác, thoát mã 2 để chặn.

**Tự định dạng sau khi sửa** (PostToolUse trên Write|Edit): chạy linter hoặc formatter trên file vừa đổi, gửi output lại cho Claude.

**Kiểm tra kiểu sau thay đổi** (PostToolUse trên Write|Edit): chạy `tsc --no-emit` sau khi sửa TypeScript, Claude thấy lỗi và sửa các chỗ gọi.

**Ngăn code trùng lặp** (PostToolUse trên Write): khởi chạy một phiên Claude thứ hai để review code mới so với khuôn mẫu sẵn có.

**Cổng chất lượng trước khi dừng** (Stop): kiểm tra test pass hoặc file bắt buộc tồn tại trước khi cho Claude kết thúc.

**Chèn môi trường lúc khởi động** (SessionStart): ghi các câu lệnh `export` vào `$CLAUDE_ENV_FILE` để đặt biến môi trường cho phiên.

## Cần nhiều hơn một script?

Shell hook khởi chạy tiến trình mới cho mỗi sự kiện. Nếu bạn muốn trạng thái tồn tại suốt phiên, UI sống như một dải phía trên ô prompt hay một pane gắn cạnh, hoặc gọi trực tiếp tính năng của Claude Code, hãy viết một [mod](^Hook JavaScript chạy bên trong phiên của bạn. Xem mục mods). Mod là function hook được phát hành dưới dạng plugin.

## Mẹo

- Hooks được chụp lại lúc khởi động phiên. Khởi động lại Claude sau khi đổi cấu hình hook
- Dùng `$CLAUDE_PROJECT_DIR` trong lệnh để tham chiếu script tương đối với gốc dự án
- Dùng `/hooks` trong phiên để xem, thêm và xoá hook một cách tương tác
- Chạy `claude --debug` để xem chi tiết thực thi hook và mã thoát
- Đặt `"disableAllHooks": true` trong settings để tạm tắt mọi hook
- Giữ hook chạy nhanh. Timeout mặc định là 600 giây cho command, 30 giây cho prompt
- Đặt biến shell trong ngoặc kép (`"$VAR"` thay vì `$VAR`) và kiểm tra đầu vào. Hook script chạy với toàn quyền người dùng của bạn
- Với công cụ MCP, khớp bằng mẫu như `mcp__github__.*` hoặc `mcp__.*__write.*`
- Hook prompt và agent trả về `{"ok": true/false, "reason": "..."}` thay vì dùng mã thoát
