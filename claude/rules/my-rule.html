Khung mẫu file Rule

File rule khởi đầu, minh hoạ frontmatter glob và cách viết quy ước.

File liên quan
.claude/rules/RULES.md
.claude/rules/my-rule.md
frontmatter
paths["src/**/*.ts", "src/**/*.py"]

Quy ước mã nguồn

Mở rộng CLAUDE.md với các khuôn mẫu riêng cho file mã nguồn của ứng dụng.

Xử lý lỗi

  • Luôn dùng kiểu lỗi của dự án, không bao giờ throw chuỗi thô hay lỗi chung chung
  • Ghi log chi tiết ở nội bộ, chỉ trả thông báo an toàn cho bên gọi
  • Bắt lỗi ở ranh giới (API handler, event listener), không bắt sâu trong code tiện ích

Đặt tên

  • Hàm trả về boolean bắt đầu bằng is, has hoặc should
  • Hằng số dùng UPPER_SNAKE_CASE, biến và hàm dùng camelCase hoặc snake_case theo quy ước của ngôn ngữ
  • Tên file khớp với export chính: UserService nằm trong user-service.ts hoặc user_service.py

Import và phụ thuộc

  • Nhóm import: thư viện chuẩn trước, package bên ngoài thứ hai, module nội bộ thứ ba
  • Không import vòng. Nếu hai module cần nhau, tách logic dùng chung ra module thứ ba
  • Ưu tiên import tường minh hơn wildcard

Đây là file rule khởi đầu. Tên file my-rule.md chỉ là ví dụ. Hãy đặt tên rule có ý nghĩa: code-style.md, testing.md, error-handling.md.

Giải phẫu file này

Phần frontmatter (giữa hai dấu --- ở đầu) là tuỳ chọn nhưng nên có. Nó quyết định khi nào rule này được nạp:

  • paths: các mẫu file kích hoạt rule. Khi Claude đọc file khớp với bất kỳ mẫu nào, rule này được nạp vào bối cảnh

Định dạng một dòng (paths: ["pattern1", "pattern2"]) hợp với danh sách ngắn. Với danh sách dài, dùng định dạng YAML nhiều dòng:

yaml
---
paths:
  - "src/**/*.ts"
  - "src/**/*.py"
  - "lib/**/*.js"
---

Nếu bỏ hẳn frontmatter (hoặc bỏ paths), rule luôn được nạp, hoạt động như một phần mở rộng của CLAUDE.md.

Phần thân chứa các quy ước thực tế. Viết chúng thành chỉ dẫn trực tiếp. Gạch đầu dòng và tiêu đề ngắn hiệu quả nhất vì Claude đọc lướt cấu trúc giống như một lập trình viên.

Ví dụ mẫu đường dẫn

Mẫu Khớp với
"src/**/*.ts" Mọi file TypeScript trong src/
"**/*.test.{ts,js}" File test ở mọi độ sâu
"src/**/*.py" File Python trong thư mục src
"Dockerfile*" Dockerfile ở gốc dự án
"**/*.sql" Mọi file SQL ở bất kỳ đâu trong dự án

Viết vào Rule hay vào CLAUDE.md

Đặt quy ước vào file rule khi chúng:

  • Chỉ áp dụng cho loại file hoặc thư mục cụ thể
  • Sẽ gây nhiễu cho người làm ở phần khác của codebase
  • Đủ chi tiết để làm phình CLAUDE.md nếu viết thẳng vào đó

Giữ quy ước trong CLAUDE.md khi chúng:

  • Áp dụng chung (đặt tên, quy trình git, quy trình PR)
  • Đủ ngắn để việc tách ra tốn công hơn lợi ích
  • Cần luôn hiện diện bất kể Claude đang đọc file nào

Rules vs Skills

Rules và skillsSkills là gói hướng dẫn tái sử dụng với SKILL.md, script, tài liệu tham khảo tuỳ chọn, và gọi được bằng /tên-skill đều cung cấp chỉ dẫn, nhưng giải quyết vấn đề khác nhau:

Rules Skills
Định dạng Markdown với frontmatter paths tuỳ chọn SKILL.md với frontmatter name/description bắt buộc
Mục đích Quy ước thụ động được nạp vào bối cảnh Chỉ dẫn chủ động, có thể gọi được
Kích hoạt Tự động, theo mẫu file Tự động hoặc qua /tên-skill
File hỗ trợ Không có (chỉ file .md) scripts/, references/, assets/
Tác dụng phụ Không (chỉ là bối cảnh thụ động) Có thể chạy lệnh và sửa file

Dùng rules cho "luôn theo các khuôn mẫu này khi đọc những file này". Dùng skills cho "đây là cách thực hiện tác vụ cụ thể này".

security.md ["src/**/*", "config/**/*"]
documentation.md ["**/*.md", "docs/**/*"]

## Rules vs Skills

Rules và [skills](^Skills là gói hướng dẫn tái sử dụng với SKILL.md, script, tài liệu tham khảo tuỳ chọn, và gọi được bằng /tên-skill) đều cung cấp chỉ dẫn, nhưng giải quyết vấn đề khác nhau:

| | Rules | Skills |
|---|---|---|
| Định dạng | Markdown với frontmatter `paths` tuỳ chọn | SKILL.md với frontmatter name/description bắt buộc |
| Mục đích | Quy ước thụ động được nạp vào bối cảnh | Chỉ dẫn chủ động, có thể gọi được |
| Kích hoạt | Tự động, theo mẫu file | Tự động hoặc qua `/tên-skill` |
| File hỗ trợ | Không có (chỉ file .md) | scripts/, references/, assets/ |
| Tác dụng phụ | Không (chỉ là bối cảnh thụ động) | Có thể chạy lệnh và sửa file |

Dùng rules cho "luôn theo các khuôn mẫu này khi đọc những file này". Dùng skills cho "đây là cách thực hiện tác vụ cụ thể này".
