Quyền & an toàn

Checkpoint, chế độ quyền, rule allow/ask/deny, Auto mode và sandbox: mỗi lớp bảo vệ gì và không bảo vệ gì.

Cập nhật 15/11/2026 · 3 phút đọc

Claude chạy được mọi lệnh bạn chạy được. Đó là sức mạnh, và cũng là lý do Claude Code có nhiều lớp bảo vệ. Hiểu từng lớp giúp bạn vừa an toàn vừa không bị hỏi quá nhiều.

Các lớp bảo vệ

 Hành động Claude muốn làm
        │
        ▼
 ① Rule deny / ask / allow   ← luôn áp dụng, ở mọi chế độ
        │
        ▼
 ② Hook PreToolUse           ← script của bạn, chặn được
        │
        ▼
 ③ Chế độ quyền              ← Manual hỏi · Accept Edits · Plan · Auto (bộ phân loại)
        │
        ▼
 ④ Sandbox                   ← giới hạn file & mạng ở cấp hệ điều hành
        │
        ▼
 Thực thi  →  ⑤ Checkpoint (sửa file thì hoàn tác được)

① Rule quyền: lớp cứng nhất

Rule Tác dụng
allow Duyệt trước, không bao giờ hỏi
ask Luôn hỏi, kể cả ở Bypass Permissions
deny Chặn ở mọi chế độ, kể cả Auto và Bypass

Thứ tự đánh giá: deny → ask → allow, rule khớp đầu tiên thắng.

json
{
  "permissions": {
    "allow": ["Bash(pnpm tsc --noEmit)"],
    "ask": ["Bash(git push *)"],
    "deny": ["Read(./.env)", "Read(./.env.local)", "Read(./secrets/**)"]
  }
}

Rule Read(./.env) chặn cả lệnh cat .env vì Claude Code nhận ra các lệnh đọc file phổ biến. Nhưng rule khớp lời gọi công cụ, không khớp ý định: một script tự mở file thì không bị chặn, và rule deny WebFetch cho một domain không chặn curl tới domain đó, trừ khi bật sandbox.

② Hook: luật do bạn viết

Hook PreToolUse nhận JSON mô tả hành động sắp xảy ra và thoát mã 2 để chặn. Dùng cho luật riêng của dự án, ví dụ cấm sửa thư mục migrations/.

③ Chế độ quyền

Chế độ Chạy không cần hỏi
Manual Chỉ đọc
Accept Edits Đọc, sửa file, lệnh file thông dụng
Plan Chỉ đọc, không sửa
Auto Hầu hết mọi thứ; bộ phân loại chặn hành động rủi ro
Don't Ask Chỉ thứ đã duyệt trước (CI)
Bypass Permissions Mọi thứ (chỉ trong container cô lập)

Từ các bản gần đây, phiên terminal và VS Code tương tác bắt đầu ở Auto mode khi tài khoản đủ điều kiện. Auto mode chặn mặc định những việc như curl | bash, deploy production, force push, gửi dữ liệu nhạy cảm ra ngoài.

Auto mode là một model phán đoán, không phải luật cứng. Nó tốt, nhưng có thể sai. Những gì "không bao giờ được xảy ra" phải nằm trong rule deny hoặc hook.

Hai cực đều có giá: Manual an toàn nhưng tới lần hỏi thứ mười bạn sẽ duyệt mà không đọc; Bypass duyệt tất cả, chỉ hợp với container dùng một lần.

④ Sandbox

/sandbox giới hạn lệnh shell của Claude ở cấp hệ điều hành (macOS, Linux, WSL2) về file và mạng, và tự áp các rule Read deny và WebFetch(domain:…). Với bất cứ thứ gì liên quan bảo mật, dùng cả rule lẫn sandbox.

⑤ Checkpoint: lưới an toàn cho file

Trước khi Claude sửa file, nó chụp lại nội dung cũ. Esc Esc hoặc /rewind để quay lại.

Giới hạn cần biết:

  • Chỉ bao phủ file sửa bằng công cụ sửa file của Claude; file chỉ bị lệnh Bash đụng tới thì không khôi phục được
  • Không hoàn tác được tác động bên ngoài: database, API, deploy, tin nhắn đã gửi
  • Dùng cùng với git, không thay git

Ai đặt luật

Vị trí Áp cho
~/.claude/settings.json, .claude/settings.local.json Chỉ bạn
.claude/settings.json Cả nhóm (deny có hiệu lực ngay; allow chờ mỗi người tin cậy thư mục)
Managed settings Cả tổ chức, không ai ghi đè được

Điều rút ra

  1. Dùng mặc định (Auto) cho việc hằng ngày; thêm rule deny cho thứ tuyệt đối cấm
  2. Giữ bộ luật cưỡng chế nhỏ: mỗi rule đôi khi chặn nhầm và cần người duy trì
  3. Commit trước khi để Claude làm việc lớn; checkpoint không thay được git
