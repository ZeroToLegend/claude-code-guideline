Các mảnh ghép

CLAUDE.md, rules, skills, hooks, subagent, MCP, plugins nằm ở đâu trong vòng lặp, và khi nào dùng cái nào.

Cập nhật 15/11/2026 · 3 phút đọc

Claude Code có nhiều cách mở rộng, và người mới thường bối rối không biết nên dùng cái nào. Cách dễ nhất để phân biệt: hỏi ai quyết định và khi nào nó được nạp.

Hai loại chỉ dẫn

Claude quyết định (không tất định) Claude Code cưỡng chế (tất định)
Làm gì Prompt, CLAUDE.md, skill Claude tự chọn Hook, skill chỉ bạn được gọi
Được đụng vào đâu Bộ phân loại của Auto mode Rule deny, sandbox, managed settings
Khi nào là xong Yêu cầu bằng chứng, /goal, /code-review Test, typecheck, hook Stop, CI
Tiêu bao nhiêu Mức effort --max-turns, --max-budget-usd, hạn mức chi tiêu

Phần lớn thời gian, bạn muốn Claude quyết định: hầu hết quy tắc đều có ngoại lệ, và khi có code trước mặt, Claude thường phán đoán tốt hơn một quy tắc viết sẵn. Loại tất định dành cho thứ luôn luôn (hoặc không bao giờ) được xảy ra.

Nếu bạn cứ thêm chữ IMPORTANT vào một dòng CLAUDE.md mà Claude vẫn bỏ qua, dòng đó nên là một hook. Ngược lại, hook cho thứ chỉ là sở thích thì nên xoá và để Claude tự quyết.

Bản đồ các mảnh ghép

Mảnh ghép Là gì Nạp khi nào Dùng cho
CLAUDE.md Chỉ dẫn markdown Mọi phiên Lệnh build/test, quy ước không nằm trong code, cạm bẫy
Rules Chỉ dẫn theo loại file Khi Claude đọc file khớp paths Quy ước chỉ đúng với một phần codebase
Skills Gói quy trình / kiến thức Mô tả luôn có; nội dung khi dùng Quy trình của nhóm: release, review, runbook
Output styles Chỉ dẫn về cách trả lời Mọi request trong phiên Giọng điệu, độ dài, vai trò của Claude
Hooks Script chạy ở sự kiện cố định Luôn, do Claude Code chạy Việc phải xảy ra mọi lần: format, chặn, kiểm tra
Permissions Rule allow / ask / deny Luôn, do Claude Code áp Giới hạn lệnh và file Claude được đụng
Subagents Claude riêng với context riêng Khi được giao việc Việc nhiều output, song song, reviewer độc lập
Workflows Script điều phối nhiều subagent Khi chạy Việc quy mô hàng chục tới hàng trăm agent
MCP Kết nối hệ thống ngoài Tên công cụ luôn có; schema khi dùng Issue tracker, database, công cụ không có CLI
Plugins Gói các thứ trên Khi được bật Chia sẻ cấu hình giữa repo và nhóm

Chọn cái nào: cây quyết định nhanh

  1. Claude cần biết một điều về dự án? → CLAUDE.md (nếu chỉ đúng với vài thư mục → rules)
  2. Đó là một quy trình nhiều bước, dùng thỉnh thoảng? → skill (có tác dụng phụ như deploy → disable-model-invocation: true)
  3. Phải xảy ra mọi lần, không ngoại lệ? → hook
  4. Không bao giờ được xảy ra? → rule deny (kèm sandbox nếu liên quan bảo mật)
  5. Việc tạo nhiều output, hay cần góc nhìn độc lập? → subagent
  6. Cần dữ liệu từ hệ thống khác? → CLI có sẵn (gh, aws…), không có thì MCP
  7. Muốn người khác dùng lại? → plugin

Chúng kết hợp với nhau

Ví dụ với một dự án TypeScript:

  • CLAUDE.md: lệnh pnpm vitest run <file>, pnpm tsc --noEmit, "dùng helper lỗi trong src/lib/errors.ts"
  • .claude/rules/api.md: quy ước riêng cho src/api/**
  • .claude/skills/release/: quy trình release, chỉ chạy khi bạn gõ /release
  • Hook PostToolUse: chạy Prettier sau mỗi lần sửa file
  • Rule deny: Read(./.env)
  • Subagent reviewer chỉ có Read, Grep, Glob: review không sửa được gì

Phạm vi: của ai?

Hầu hết mảnh ghép có hai bản: trong .claude/ của dự án (commit, cả nhóm dùng) và trong ~/.claude/ (chỉ bạn, mọi dự án). Ghi đè cá nhân cho một dự án đặt ở settings.local.json và CLAUDE.local.md. Tổ chức có thể áp managed settings đứng trên tất cả.
